# PB-015 — Biểu mẫu nhà tuyển dụng

## Phạm vi

Trang `source_code/client/pages/employer.html` dùng lại HTML/CSS/JavaScript và phiên đăng nhập hiện có.
Không triển khai lại vòng đời tin của PB-014, không thay đổi migration và không dùng dữ liệu mẫu trong sản phẩm.

- `employer.html#company`: tạo/sửa hồ sơ công ty, xem trạng thái và lý do từ chối, lưu rồi gửi duyệt lại.
- `employer.html#job`: tạo tin mới.
- `employer.html?job_id=42#job`: nạp và sửa tin nháp/bị từ chối có ID 42.
- Trang chủ có liên kết “Không gian tuyển dụng” sau khi đăng nhập bằng tài khoản EMPLOYER.
- Chưa đăng nhập: chuyển sang đăng nhập với URL quay lại đúng biểu mẫu.
- Sai vai trò: không mở biểu mẫu. Thành viên MEMBER chỉ xem hồ sơ công ty, không sửa/gửi lại.

Form giữ giá trị khi lỗi, hiển thị lỗi theo trường, khóa thao tác khi đang gửi, cảnh báo trước khi rời trang có thay đổi chưa lưu.
Các nội dung từ máy chủ được hiển thị bằng `textContent`/`Option`, không chèn HTML.

## API đã có và phần bổ sung

API công ty được dùng đúng với PB-013 hiện có:

| Method | URL dưới `/api/v1` | Mục đích |
| --- | --- | --- |
| GET | `/auth/me` | Xác minh tài khoản và vai trò |
| GET | `/employer/company` | Nạp hồ sơ; 404 được hiểu là chưa có hồ sơ |
| POST | `/employer/company` | Tạo mới |
| PATCH | `/employer/company` | Lưu thay đổi |
| POST | `/employer/company/resubmit` | Gửi lại hồ sơ bị từ chối sau khi lưu |
| GET | `/categories` | **Bổ sung trong PB-015**: đọc ngành nghề và tỉnh/thành đang hoạt động từ DB |

`GET /categories` trả về:

```json
{
  "industries": [{"id": 1, "name": "Công nghệ thông tin"}],
  "provinces": [{"id": 2, "name": "Hà Nội"}]
}
```

Không hardcode ID danh mục theo seed. Nếu danh mục rỗng/lỗi, chặn form và cho thử tải lại.
Hồ sơ cũ có ID danh mục đã ẩn được giữ nguyên trong form khi nạp; backend vẫn quyết định tính hợp lệ khi lưu.

## Hợp đồng tích hợp PB-014 (chưa có backend trong workspace)

**Các endpoint bên dưới là hợp đồng đề xuất mà frontend đang gọi, chưa phải API đã triển khai.**
Owner PB-014 cần xác nhận hoặc đổi ánh xạ tập trung trong `assets/js/employer-api.js` trước khi nghiệm thu end-to-end.

| Method | URL dưới `/api/v1` | Yêu cầu |
| --- | --- | --- |
| GET | `/employer/jobs/{id}` | Chi tiết riêng cho thành viên công ty, kể cả tin nháp/bị từ chối; không dùng API công khai để đọc nháp |
| POST | `/jobs` | Tạo tin nháp, trả bản ghi đầy đủ có ID |
| PATCH | `/jobs/{id}` | Sửa tin thuộc công ty; tin bị từ chối được lưu thành nháp theo SRS |
| POST | `/jobs/{id}/submit` | Gửi duyệt tin đã lưu, trả bản ghi đầy đủ trạng thái PENDING |

Tất cả request dùng `Authorization: Bearer <JWT>`. Backend phải kiểm tra tài khoản hoạt động,
vai trò, thành viên công ty, công ty đã duyệt và trạng thái tin ở mỗi request; chặn ở frontend không thay thế phân quyền server.

Body tạo/sửa:

```json
{
  "title": "Lập trình viên Backend",
  "industry_id": 1,
  "province_id": 2,
  "work_address": "Hà Nội",
  "description": "Phát triển API",
  "requirements": "Có kiến thức Python",
  "benefits": null,
  "salary_min": null,
  "salary_max": null,
  "salary_currency": "VND",
  "experience_level": null,
  "employment_type": "FULL_TIME",
  "positions": 1,
  "deadline": "2026-12-31"
}
```

Không gửi `company_id`, `created_by`, `status`, thông tin duyệt hoặc `view_count` từ form;
backend tự suy ra và kiểm soát các trường này.
Response là object trực tiếp có các trường trên cùng `id`, `company_id`, `status`, `reject_reason`.
ID là JSON number. Trường không có giá trị trả null.

- Lưu nháp: bắt buộc tiêu đề tối đa 200 ký tự; các trường khác có thể null, nhưng nếu nhập phải hợp lệ.
- Gửi duyệt: bắt buộc tiêu đề, mô tả, yêu cầu, tỉnh/thành, địa chỉ làm việc, hình thức, hạn nộp.
- Số lượng là số nguyên dương; lương là số nguyên không âm, min <= max; frontend giới hạn trong safe integer của JS.
- Hạn nộp phải là ngày hợp lệ từ hôm nay trở đi, lấy ngày theo Asia/Ho_Chi_Minh.
- Giới thiệu công ty và các đoạn văn tin tối đa 10.000 ký tự; địa chỉ tối đa 255.
- Frontend hiện chỉ nhập lương VND. Không cho sửa tin tiền tệ khác để tránh đổi đơn vị âm thầm.
- Chỉ sửa nháp/bị từ chối trong PB-015. Đóng/mở lại/gia hạn thuộc luồng khác.
- Lưu trước, gửi duyệt sau. ID được đưa vào URL ngay sau khi lưu thành công; gửi duyệt lỗi thì thử lại bằng PATCH cùng ID.
- Khi API PB-014 chưa có hoặc lỗi, hiển thị lỗi, giữ nội dung form, không báo lưu thành công.

Lỗi trả theo FastAPI: `{"detail":"Thông báo"}` hoặc 422 với `detail: [{loc:["body","field"],msg:"..."}]`.
404/403 cho tin không thuộc quyền truy cập; 409 cho xung đột trạng thái.

## Chạy và kiểm tra

Backend cần cài requirements, cấu hình DB, chạy migration và seed theo `server/migrations/README.md`.
Không chạy migration/seed tự động từ frontend.

```powershell
cd source_code/server
python run.py
```

Phục vụ client bằng HTTP, không mở trực tiếp file HTML:

```powershell
cd source_code/client
python -m http.server 5500
```

Mở `http://localhost:5500/pages/employer.html`.
API mặc định `http://127.0.0.1:8000/api/v1`, dùng lại cấu hình `VIECO_API_BASE_URL` hoặc
`localStorage.vieco_api_base_url` của `auth-api.js` khi cần.

Kiểm thử frontend (DOM mô phỏng bằng jsdom, API được mock; không thay thế browser/E2E):

```powershell
cd source_code/client
npm ci
npm test
```

Kiểm thử API danh mục và hồi quy công ty:

```powershell
cd source_code/server
python -m pytest tests/test_catalog.py tests/test_company.py -q
```
